# 用户运行偏好

- 用户要求 Balance/Homie 和推车模型在准备阶段前已加载并完成首次推理预热，准备阶段持续读取历史帧，启动策略时保留有效历史。推车未启用时只能影子推理，不能执行或将影子结果记为已执行动作。准备阶段可后台提前启动只读相机；推车有效历史需要 ID 0/1 航向，缺失相机不得阻止普通混合策略。

- 用户确认推车模式的上肢 PD：肩 pitch/roll 100/2、肩 yaw 50/2、肘 50/2、腕 roll/pitch/yaw 20/1、腰 yaw 300/3（Kp/Kd）。由 Viser 在启用推车时请求，C++ 使用独立上肢模式执行目标与增益；退出推车恢复原 Balance/Homie 上肢增益。腿部模型切换与手指抓握参数不随之修改。

- 用户于 2026-10-16 明确要求试用推车腰臂目标的线性插值：高层仍约 50 Hz，C++ 在 200 Hz 下用 20 ms 从最后实际下发目标插到最新终点。提前到来的新目标从当前下发值接续，延迟到达时保持已完成终点，不外推。仅腰 yaw 和双臂 15 关节，腿部保持原直接目标，Dex3 保持自身逻辑。归零/相机或抓握暂停须显式取消未完成插值并保持当前目标；B 在 C++ 立即冻结腰臂，L2/显式阻尼停止/故障优先。PD、关节/名义力矩保护仍保留。`pushcart_upper_pd.json` 的 `target_interpolation_s=0.02` 启用，0 可恢复直接目标；变更后完整重启。日志区分请求终点与实际插值目标，力矩估计取实际下发值，不得宣称这仍与训练时的目标保持方式完全一致。

- 用户已确认小车 AprilTag 为 ID 0 和 1；相机融合和高层接收只允许这两个 ID，背景 ID 2 等不得作为小车航向。

- 推车和普通行走统一从原 `Viser/run.sh` 启动，不在 `G1_high_policy_deploy` 保留另一套网页或启动包装。先准备、启动混合策略站立、人工摆车并抓握调试，然后用户自行选择启用推车；未启用时保持普通混合策略，不能以相机或抓握未就绪阻止普通行走。
- 推车显示使用训练仓库的小车 OBJ/URDF。机器人机身保持反馈同步；网页手指参考模型使用本机当前调整好的抓握参数，并跟随后续网页修改及文件加载，不覆盖同事正在调的抓握文件，不使用训练资产中烘焙的手指角度。小车只有航向测量而没有标签位置标定时，必须明确标为参考位置。

- 用户已明确纠正坐标需求：网页 vx/vy 始终沿机器人当前机身前后/左右轴，不按启动时世界/固定坐标旋转 XY。IMU 航向外环只修正 wz；平移各方向均可保持骨盆航向，手动主动转弯释放旧航向。用户于 2026-10-16 最新明确要求推车也经过下层 Homie 的航向 Kp 修正：发布配置默认 active，行走与推车共用网页参数，Kp=1.0、Ki=Kd=0、纠偏上限 ±0.15 rad/s；shadow 仅记录，disabled 关闭，显式选择仍须尊重。推车来源为 PUSHCART，参考航向按上一拍高层给出的机器人 wz（纠偏前）推进，参考误差限 ±0.2 rad，不能用小车任务 wz 或纠偏后的 wz 积分，也不能套用手动转向死区锁住旧朝向。归零/减速期间停止追加纠偏，实际选中的速度写入执行历史。不要恢复旧 EXTERNAL 绕过推车 Kp 的逻辑或 world XY 变换。
- 用户最新要求：`logs/sessions/` 只保留最近 5 次实际产生机器人本体反馈的真机会话，`observe` 和 `control` 合并计数。空启动不占名额；每次运行独立目录，第 6 次有数据后自动删除最旧一次。
- 每次保存机器人反馈、命令/实际目标与增益、Balance/Homie 两套模型原始动作输出、Homie 估计器输出、必要运行事件、简短启动元数据和结束统计。禁止复制 ONNX/其他模型、URDF/网格、源码、部署配置或整个项目快照；禁止逐帧重复保存神经网络完整输入历史。用户明确要求保留模型输出用于分析：同一 telemetry 帧必须保存两套原始动作及 Homie 三维速度估计、32 维原始隐变量和归一化隐变量，并与反馈 tick/推理时间对齐；没有新推理时标 null，禁止重复旧值冒充新输出。不得把估计值标为实测值，也不能在未核实训练目标尺度时声称原始估计值单位是 m/s。运行模型仅引用相邻部署包。
- 不要往项目添加杂七杂八的东西：禁止在项目内创建 analysis、archives、备份压缩包、临时报告、测试输出、截图和重复日志。测试使用系统临时目录并自动清理；诊断默认打印到终端，回放输出到系统临时目录。不要为了留痕再创建报告文档。
- 目录固定：网页入口在 `Vender/`，配置在 `config/`，测试在 `test/`，可复用控制/通信/记录模块在 `core/`，诊断工具在 `tools/`，必要说明在 `docs/`；根目录仅保留 README、AGENTS、启动/安装脚本和环境目录。移动文件必须同步导入、脚本和文档路径。
- 阻尼停止后，“接管网页操作”应恢复只读桥接并清除旧停止请求；必须重新点击接管底层、准备、启动策略。新停止请求始终优先，不允许旧队列命令复活运动。网页持有者断线后必须释放所有权，允许新网页重新接管。
- `./Viser/run.sh` 无参数默认使用 `--mode control --interface eth0 --port 8086`；显式传入 `--mode sim/observe`、`--interface` 或 `--port` 时必须尊重覆盖值。
- 速度滑条初始值必须全部为零；启动策略时实际策略速度命令必须为零。用户于 2026-10-15 明确要求按自训 456/12 Balance 的切换训练对齐：命令采用 dt/0.4 的一阶滤波，自动模式在过滤后原单位命令范数低于 0.05 时立即选择 Balance，并将当前命令置零；取消精确零命令后的 0.5 秒等待和切换目标的 0.5 秒混合。正常策略目标直接交给 PD，不额外用 10 rad/s 目标变化率拖慢动作，保留关节范围、名义 PD 力矩和独立健康保护。切换继承真实执行的六帧历史，上一动作取上一拍选中输出并按训练裁剪，后台未执行输出只记录。网页松手仍以 250 ms 心跳超时识别，导航超时仍使用原始命令时间，重复转发不得续期。归零按钮、导航零命令和关闭运动门启动相同滤波减速；时间随起始速度而变（0.6 m/s 约 0.98 秒降到阈值，另计松手检测），不再是固定 1 秒截止。减速中不反向、不增速、不产生新航向纠偏，排队运动不能打断；阻尼停止、反馈故障、持有者断线及实体 B/L2 按原逻辑立即停止。不得用腿部速度或骨盆角速度作为 Balance 接管条件。
- 导航保留 Nav2/DWB 路径跟随与避障。`NAVIGATION` 来源使用随导航角速度推进的骨盆参考航向，不能套用手动转向死区锁住旧航向；导航参数在 `nav/locomotion/motion_config.json`，Viser 手动调试仍使用自身配置与原有保向逻辑。
- 排查控制性能时区分神经网络推理耗时、策略实际完成频率、观测到动作延迟以及 DDS/真机响应；离线 50 Hz 结果不能冒充实机闭环验证。
- Dex3 位置超限仅为警告，不能阻止接管或准备，也不能导致运行中的机身全局停止。手指恢复失败或超时只结束本次恢复并警告，保留机身控制；恢复 Kp 从 0.5 在 1 秒内升至 2，最长 3 秒。用户进一步要求：正常控制中的手部 SDK 故障、通信失联、手部 DDS 发送/初始化异常只暂停手部并警告，不得成为机身全局故障，不得释放底层控制，也不能阻止机身准备。手部通信恢复后必须明确重新启用，不能自动续跑旧动作。机身健康检查、机身通信故障及显式停止仍按原规则处理。
- 用户最新要求：腿部、腰部、手臂和 Dex3 的实测角度超出 URDF/配置参考范围一律只警告，不得作为全局故障，不得导致全身失能或阻止接管/发起准备/继续策略。机身有限值越界请求目标采用限幅；位置范围与名义 PD 力矩约束无交集时只降低该关节增益并警告，不能全身停机。参考范围不等于真机硬件边界。其他独立保护（SDK 机身故障、无效数值、通信/指令超时、倾角异常及显式停止）继续保留。
- 用户于 2026-10-16 明确要求：准备姿态超过 10 秒未到位只能警告，不得进入 FAULT、阻尼退出或撤掉机身位置支撑。保持准备目标及正常 Kp/Kd，网页显示未到位关节；实测到位后解除警告并允许手动启动策略。不得恢复“准备超时全身停机”的旧逻辑。
- 用户于 2026-10-16 最新要求：暂不提高左右腕 roll（SDK 19/26）的 Kp，Balance/Homie 两份独立 PD 配置均恢复为原来的 20；Kd 保持 0.5，腕 pitch/yaw 的 Kp 保持 20。
- 用户于 2026-10-16 要求两种可选上半身准备姿态：默认沿用 `G1_Upper_Initpose/deploy_upper_hold.yaml`，第二套为同目录 `deploy_upper_arms_down.yaml`，双肘 +90°、左肩 roll +10°、右肩 roll −10°、其余手臂关节 0°；YAML 使用弧度。两套下半身共用 `G1Deploy_BalanceHomie/config/deploy.json` 的 `default_q_sdk29` 前 12 项。网页持有者在准备前选择，选择本身不动作，准备请求发出后立即锁定并在后续策略中保持；不联动 Dex3，不改变 PD 配置。
- 用户于 2026-10-15 要求：常规流程中接管底层、进入准备姿态和启动机身策略均不得自动使能 Dex3 或让手部归零，避免手臂与手指同时运动碰撞躯干。准备完成后，首次明确点击 Dex3 姿态切换按钮才使能并从实时反馈角度抓握；后续切换抓握／归零，按补偿勾选状态设置目标。未使能与故障暂停须区分显示，故障后仍需明确重新启用。
