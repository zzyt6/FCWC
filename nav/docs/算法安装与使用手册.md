# Unitree G1 Mid-360 FAST-LIO / Nav2 算法安装与使用手册

> 文档日期：2026-10-14（迁移版）  
> 适用项目：`/home/unitree/CWC/nav`  
> 适用平台：Unitree G1、Livox Mid-360、Ubuntu 20.04、ROS 2 Foxy、aarch64

本文按 10 个部分说明当前项目的安装、建图、地图转换、定位导航、检查与安全操作。除非特别说明，所有命令都在 G1 本体计算机上执行。本项目只包含建图和常规点到点导航；导航运控使用我们自己的 Balance/Homie 策略（见 `../README.md`）。

## 1. 算法功能与整体链路

本项目用于小型室内环境的三维建图和二维自主导航，核心链路如下：

```text
G1 官方 Mid-360 服务
  ├─ /utlidar/cloud_livox_mid360（点云，约 10 Hz）
  └─ /utlidar/imu_livox_mid360（IMU，约 200 Hz）
                    │
                    ▼
                 FAST-LIO
  ├─ /Odometry、/path              激光惯性里程计
  ├─ /cloud_registered             当前配准点云
  ├─ /Laser_map                    实时全局点云地图
  └─ maps/*.pcd                    保存的三维地图
                    │
                    ├─ PCL 地面分割 + OctoMap 投影 → map.pgm/map.yaml
                    │
                    └─ G1 官方腰部链 → /Odometry_base、base_nav
                                             │
                                             ▼
                           AMCL + Nav2 + 实时点云避障
                                             │
                                             ▼
                           /cmd_vel → 安全门 → 自研 Balance/Homie 运控（nav/locomotion）
```

主要模块如下：

| 模块 | 作用 | 位置 |
| --- | --- | --- |
| FAST-LIO | 激光与 IMU 紧耦合里程计、增量建图 | `src/fast_lio` |
| G1 坐标与控制桥 | 腰部坐标换算、LowState、速度安全门 | `src/unitree_g1_kinematics` |
| 地图处理 | PCD 地面分割、OctoMap 投影、障碍过滤 | `src/unitree_nav2_core` |
| Nav2 扩展 | 旋转控制、进度检查插件 | `src/nav2_*` |
| Web 导航 | Canvas、地图管理、AMCL/Nav2 编排、运控面板、安全联锁 | `src/unitree_nav2_web` |
| 导航运控执行 | 复用 `Viser/core` 控制器执行 `/cmd_vel` | `locomotion/` |
| 建图可视化 | Viser 当前帧、全局地图和轨迹显示 | `src/unitree_fastlio_baseline` |

注意：`src/livox_ros_driver2` 只提供 FAST-LIO 编译所需消息类型。运行时使用 G1 官方 LiDAR service，**不要再启动另一套 Livox 驱动**。

## 2. 硬件、系统与安全前提

开始安装前确认以下条件：

- G1 和 Mid-360 工作正常，官方雷达服务已经启动。
- `eth0` 连接 G1 本体 DDS 网络；`wlan0` 供远程浏览器访问网页。
- 系统为 Ubuntu 20.04，ROS 发行版为 Foxy，CPU 架构为 aarch64。
- 已安装 Unitree SDK2 C++；导航运控还需要相邻的 `G1Deploy_BalanceHomie`、`G1_URDF`、`G1_Upper_Initpose`、`Viser` 目录和 CWC conda 环境（onnxruntime）。
- 实机运动必须有现场监护人员和可立即使用的实体急停。
- 建图阶段使用宇树本体运控行走；导航阶段由网页“运控”面板接管底层，接管后没有姿态支撑，必须吊装或扶稳。

环境检查命令：

```bash
uname -m
lsb_release -ds
test -f /opt/ros/foxy/setup.bash && echo "ROS 2 Foxy: OK"
test -f /home/unitree/cyclonedds_ws/cyclonedds_eth0.xml && echo "DDS config: OK"
```

预期 `uname -m` 输出 `aarch64`。如果硬件型号、雷达安装姿态或 G1 机型版本不同，不能直接照搬当前外参和足迹参数。

进入项目根目录，并确认三个入口脚本存在：

## 5. 配置 DDS、网卡并检查传感器

项目默认使用以下通信配置：

```bash
source /opt/ros/foxy/setup.bash
export LD_LIBRARY_PATH="$HOME/cyclonedds/install/lib:${LD_LIBRARY_PATH:-}"
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=/home/unitree/cyclonedds_ws/cyclonedds_eth0.xml
export G1_NETWORK_INTERFACE=eth0
```

`cyclonedds_eth0.xml` 应把 CycloneDDS 网络接口绑定到 `eth0` 并允许组播。启动脚本已经自动设置这些变量；仅在手工执行 ROS 命令时需要显式设置。

ROS 节点使用本机已安装的 CycloneDDS 0.10.2；其库目录须在加载所有 ROS setup 后置于 `LD_LIBRARY_PATH` 最前，避免重新选中 Foxy 的 0.7。启动脚本默认使用 `~/cyclonedds/install/lib`，可用 `UNITREE_CYCLONEDDS_LIB` 覆盖。SDK 反馈桥和运控执行器不继承这条库路径，而使用自身 SDK 的匹配库。

检查网卡和官方 Mid-360 数据：

```bash
ip -br link
ip -4 -br addr show eth0
ip -4 -br addr show wlan0
ros2 topic list -t | grep utlidar
ros2 topic hz /utlidar/cloud_livox_mid360
ros2 topic hz /utlidar/imu_livox_mid360
```

预期点云约为 `10 Hz`，IMU 约为 `200 Hz`。完成频率观察后按 `Ctrl-C` 退出。若两个话题不存在，先处理官方 LiDAR service、`eth0`、DDS 配置或组播问题，不要通过启动仓库内的 Livox driver 绕过检查。

网页服务绑定 `0.0.0.0`，远程电脑需和 G1 的 `wlan0` 位于同一局域网。IP 由 DHCP 分配时，以启动脚本打印的 URL 为准，不要固定使用某个历史 IP。

## 7. 启动 FAST-LIO 建图并保存 PCD

启动前让 G1 稳定站立，雷达无遮挡；初始化阶段保持静止，避免 IMU 重力方向和零偏估计受到扰动。不要同时运行建图和导航入口。

启动默认建图：

```bash
cd /home/unitree/CWC/nav
./run_mapping.sh
```

终端会打印 Viser 地址，例如 `http://<G1-Wi-Fi-IP>:8080`。可覆盖网页端口和地图文件：

```bash
./run_mapping.sh \
  viser_port:=8081 \
  map_output:="$(pwd)/maps/room_01.pcd"
```

建图过程中可检查：

| 话题 | 正常含义 |
| --- | --- |
| `/Odometry` | FAST-LIO 的雷达/IMU 位姿持续更新 |
| `/Odometry_base` | 换算后的 G1 腰部导航里程计 |
| `/cloud_registered` | 当前注册点云 |
| `/Laser_map` | 持续增长的全局建图层 |
| `/path` | FAST-LIO 轨迹 |

Viser 中黄色点云是当前帧，彩色点云是全局地图。需要保存时，可点击网页中的“保存实时建图层”按钮，也可在另一终端调用：

```bash
cd /home/unitree/CWC/nav
source /opt/ros/foxy/setup.bash
source install/setup.bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=/home/unitree/cyclonedds_ws/cyclonedds_eth0.xml

```

默认结果为 `maps/fastlio_map.pcd`。结束时按一次 `Ctrl-C`，等待各节点正常退出并确认 PCD 文件存在，避免直接断电。

## 8. 将 PCD 转为 Nav2 二维地图

`build.sh` 和 `run_navigation.sh` 会自动准备默认 `cf` 地图。处理新建地图时，可使用网页选择 `maps/` 下的 PCD，也可手工执行转换器：

```bash
cd /home/unitree/CWC/nav
source /opt/ros/foxy/setup.bash
source install/setup.bash

install/unitree_nav2_core/lib/unitree_nav2_core/pcd_to_nav_map \
  --input maps/room_01.pcd \
  --output-dir maps/generated/room_01 \
  --resolution 0.03 \
  --ground-z auto \
  --obstacle-min-height 0.15 \
  --obstacle-max-height 1.80 \
  --ground-band 0.15 \
  --obstacle-radius 0.04 \
  --free-radius 0.15
```

输出目录通常包括：

- `map.pgm`：Nav2 二维占据栅格图；
- `map.yaml`：分辨率、原点和图像路径；
- `map.bt`：OctoMap 数据；
- `metadata.json`：转换参数和地图统计信息。

参数含义：

| 参数 | 当前默认值 | 作用 |
| --- | ---: | --- |
| `resolution` | `0.03 m/cell` | 二维地图分辨率 |
| `ground-z` | `auto` | 使用 RANSAC 自动估计地面 |
| `obstacle-min-height` | `0.15 m` | 忽略贴近地面的噪声 |
| `obstacle-max-height` | `1.80 m` | 障碍高度上限 |
| `ground-band` | `0.15 m` | 地面带宽 |
| `obstacle-radius` | `0.04 m` | 障碍轮廓补强 |
| `free-radius` | `0.15 m` | 地面自由区补洞 |

转换后先检查 PGM 中墙体、走廊和未知区是否符合现场，再用于实机导航。手臂姿态或载荷改变后，还要重新评估 G1 足迹和膨胀半径，不能只修改地图像素。

## 9. 启动定位导航并在 Canvas 中操作

启动导航：

```bash
cd /home/unitree/CWC/nav
./run_navigation.sh
```

默认网页为 `http://<G1-Wi-Fi-IP>:8080`，rosbridge 为 `ws://<G1-Wi-Fi-IP>:9090`。使用指定地图或端口时：

```bash
./run_navigation.sh \
  map_yaml:="$(pwd)/maps/generated/room_01/map.yaml" \
  http_port:=8081 \
  rosbridge_port:=9091
```

Canvas 中必须按以下顺序操作：

1. 选择 `maps/` 中的 PCD，确认转换参数并生成、加载二维地图。
2. 点击“2D 初始位姿”，在地图上按住并拖拽，指定机器人位置和朝向。
3. 等待 AMCL 完成至少多次稳定更新，页面状态显示 `READY`；若 30 秒仍未收敛，重新核对地图和初始位姿。
4. 人工确认页面中的机器人、墙体和实时扫描与真实环境一致。
5. 吊装或扶稳后，在“运控”面板依次点 ① 接管底层、② 准备姿态、③ 启动策略，等待显示“策略运行”，再开启“G1 运动安全门”。
6. 第一次只发送前方 `0.5–1.0 m` 的短目标，确认全局路径、局部障碍和实际运动方向。
7. 任务结束时点击“停止 / 取消导航”；系统会取消 Nav2 action、关闭运动门并平滑归零。需要立即中断运动时使用实体 L2 或“阻尼停止”。

可在本体终端查看网页桥状态：

```bash
curl -fsS http://127.0.0.1:8080/api/status
```

导航与 `Viser/run.sh` 不能同时运行，两者共用部署包底层桥接。

路径跟随保留 Nav2：普通行走用 DWB，推车用 Regulated Pure Pursuit（`CartPush`）。导航骨盆航向参数独立放在 `locomotion/motion_config.json`，默认 active、Kp=1、Ki=Kd=0；参考航向随导航角速度推进，不套用 Viser 手动转向死区。需要关闭附加修正可传 `heading_mode:=disabled`。Viser 手动配置不受导航参数影响。

## 10. 停机、故障排查与算法边界

正常停机顺序：

1. 在网页中取消当前导航目标。
2. 确认 G1 运动安全门已经关闭，机器人完全静止。
3. 吊装或扶稳后，在“运控”面板点“阻尼停止”。
4. 回到启动终端按一次 `Ctrl-C`，等待节点退出。
5. 最后再按现场流程切换机器人模式或关闭设备。

常见问题：

| 现象 | 优先检查 |
| --- | --- |
| 没有 `/utlidar/*` | 官方 LiDAR service、`eth0`、DDS XML、组播和网线 |
| 有输入但没有 `/Odometry` | 点云/IMU 频率、启动时是否静止、FAST-LIO 参数和终端报错 |
| 构建找不到 `unitree_sdk2` | C++ SDK 是否安装、`unitree_sdk2Config.cmake`、`CMAKE_PREFIX_PATH` |
| 网页打不开 | 先检查本机 `curl http://127.0.0.1:8080/` 和 `ss -ltn`；8080/9090 未监听时查看启动错误；本机正常再查 `wlan0` IP、同一 Wi-Fi 和防火墙 |
| 多个 ROS 节点同时以 `-11` 退出 | 检查是否误加载 Foxy 的 CycloneDDS 0.7；用本项目入口脚本，确保新版 DDS 库在 ROS setup 后仍优先 |
| SDK 桥接以 `127` 退出并报 DDS `undefined symbol` | ROS 的 DDS 库覆盖了 SDK 库；使用入口脚本对 SDK 进程隔离库路径，不全局强制两者共用同一版本 |
| AMCL 一直不 `READY` | PCD/二维地图是否匹配现场、初始位姿方向、`/scan_localization` 是否新鲜 |
| 地图有但机器人不运动 | 运控面板是否“策略运行”、运动门、定位状态、传感器时效和 `/g1/motion_enabled`；禁止绕过安全门 |
| 运控显示“未连接” | 是否有 Viser 正在运行（端口占用）、CWC Python 环境、终端中 `g1_locomotion_executor` 报错 |
| 局部避障没有更新 | `/cloud_obstacles`、`/scan`、地面分割、4 m 扫描范围和 local costmap |
| 默认地图缺失 | 重新运行 `./build.sh`，或按第 8 节手工转换 PCD |

默认安全限制包括：`vx ≤ 0.35 m/s`、`|vy| ≤ 0.20 m/s`、`|yaw| ≤ 0.50 rad/s`，速度命令超时检测为 `0.25 s`，网页运动授权租约超时为 `1.50 s`。这些是软件上限，不是现场安全速度；首次测试应在围挡区域进一步降速。

普通导航零速、取消或关门后，调用与当前 Viser 相同的减速流程：按 0.4 秒时间常数向零滤波，命令范数低于 0.05 的同一拍切 Balance 并将当前策略命令置零。断指令先按原始命令时间检测 250 ms 超时，UDP 重传不能续期。没有固定 1 秒截止或额外 0.5 秒等待，减速时间随起始命令大小变化。减速不是运控故障，但期间不接受新目标；阻尼停止、实体 B/L2、反馈故障仍立即停止。命令归零不等同于机身实际停稳。UDP 转发使用带原始命令时间戳的 v2 协议，升级执行器后需重新编译 `unitree_g1_kinematics`。

算法边界必须明确：

- FAST-LIO 是紧耦合激光惯性里程计和增量 scan-to-map，当前没有回环检测或全局位姿图优化，长距离或重访区域可能累计漂移。
- 腰部关节只用于雷达到 `base_nav/base_link` 的坐标换算，不进入 FAST-LIO 滤波器；腿部和足端里程计也未参与估计。
- AMCL 和 Nav2 使用二维地图及 yaw-only `base_nav`；FAST-LIO 仍保留真实三维姿态。
- 当前雷达有效范围按 `0.5–10.0 m` 配置，实时避障扫描为 `4.0 m`，定位扫描为 `8.0 m`。
- 点云过滤、运动租约和 watchdog 不能替代实体急停、隔离测试区与现场监护。
